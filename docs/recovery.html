Muse Spark 1.3 operated a real local HTTP + SQLite service. After a lost acknowledgment, a stale read led to a second committed write. Muse eventually reported FAILED. A separate post-hoc tool-prefix replay demonstrates that a deterministic guard can deny the same retry.

What did we establish?

Critical distinction

When the guard denies the fourth tool call, the paths diverge. Muse's behavior after a denial was not observed. The guarded case is a post-hoc replay, not a new successful model run.

Download

No full prompts, raw tool arguments, private oracle files, API credentials, or private holdout contracts.

Safety versus completion

Hard-stop denies ambiguous repeats and avoids duplication in this case, but a precommit timeout can leave 0/1 effects. Verified server-side request-key idempotency provides a different trade-off. Neither policy by itself proves general exactly-once semantics for all systems.
